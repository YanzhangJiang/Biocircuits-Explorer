## Ownership rules

1. `NetworkIR` and `DesignSpec` field names, enums, and current version constants
   are owned by Julia source. Edit the structs/parser, regenerate the two schemas,
   and commit the deterministic output. Do not edit those generated JSON files as
   the primary change.
2. Hand-authored schemas must change with their runtime producer/consumer and a
   contract test in the same change.
3. A schema family and a concrete version are different. The current NetworkIR
   parser accepts a declared value in the `bne-ir/` family; that permissiveness is
   forward-compatibility behavior, not proof that unknown future fields have the
   intended meaning. The DesignabilitySpec normalizer, by contrast, requires the
   exact current version.
4. `additionalProperties: true` is an extension policy, not permission for a
   client to rely on arbitrary fields forever.
5. JSON Schema `$id` values identify schemas. Repository references in knowledge
   files remain relative paths so local/private checkout locations never become
   part of a public contract.

## Required change sequence

For a schema-bearing interface:

1. change the runtime owner;
2. add or update a positive and negative contract fixture;
3. update or regenerate the schema;
4. run the producer and consumer tests;
5. run schema drift/instance validation;
6. update `knowledge/catalogs/contracts.yaml` if identity, owner, or coverage
   changed;
7. document migration and sunset behavior when compatibility is not additive.

Useful commands from the repository root:

```bash
julia --project=webapp webapp/scripts/gen_schemas.jl
git diff --exit-code -- schemas/
python3 webapp/scripts/validate_artifacts.py
julia --project=webapp webapp/test/runtests.jl
cd webapp && npm run test:js && npm run test:py
python3 webapp/scripts/reader/test_reader_nofabrication.py
```

`webapp/scripts/validate_artifacts.py` implements only the draft-07 subset used by
its two configured artifact families. A pass must not be generalized to schemas
or instances it did not load.
